# Validation and Path to Operations Rewrite

Suggested replacement for the text immediately after `\section{Validations and Path to Operations}` in `main.tex`:

Our validation approach follows directly from the three deliverables. For Part 1, we will validate the Virtual Directory Interface by confirming that generic \ac{AI} clients can discover and traverse representative \ac{OPeNDAP}-enabled collections in \ac{ESDIS} without collection-specific adaptation. Success will be measured by whether the interface exposes the expected collection structure and whether autonomous crawlers can reach the same collection endpoints that expert users reach manually.

For Part 2, we will validate the agentic metadata-generation workflow by comparing the generated markdown documents against authoritative sources already used by the Earthdata community, including collection metadata, \ac{CF} metadata, and the results of direct \ac{DAP4} inspection. The system will be judged on whether it produces complete, evidence-linked metadata summaries, correctly flags uncertainty or disagreement, and avoids asserting facts that are not supported by the data or upstream metadata. Members of the project team, together with collaborators familiar with the selected \ac{ESDIS} collections, will review a representative sample of these generated documents to confirm that they are accurate and useful for downstream retrieval tasks.

For Part 3, we will validate operational usefulness by testing whether an autonomous client can use the embedded guidance to make correct data access and subsetting requests on the first attempt more often than a baseline workflow that relies only on conventional metadata records. We will evaluate whether the resulting requests are retrieval-correct, reduce avoidable iteration, and capture dataset-specific constraints that are often learned today only through expert experience.

The path to operations is intentionally incremental because this project extends existing \ac{OPeNDAP} and Hyrax capabilities rather than introducing a separate service that must be adopted independently. The Virtual Directory Interface can be incorporated into Hyrax deployments using the same software distribution mechanisms already used for \ac{OPeNDAP} server updates. The metadata-generation software will be maintained in an open repository so that it can be rerun as collections evolve, inspected by \ac{NASA} partners, and improved through operational experience. The generated markdown guidance can be reviewed by domain experts before publication and then served through existing \ac{DAP4} responses, allowing adoption first in pilot collections and then, if successful, across additional \ac{ESDIS} holdings. This staged deployment provides a practical route from prototype to operational use while keeping validation, expert review, and software maintenance aligned with current Earthdata practices.
